| [ADR-003](./ADR-003-event-log-genesis-fold-persistence.md) | Append-only event log, immutable genesis seed, and fold to the review model | product | Accepted (amended 2026-07-01, 2026-07-02, 2026-07-02, 2026-07-07) | Portfolio history is an append-only event log on an immutable genesis seed; current and as-of state are a pure fold into the existing `FundReviewData`. Trust moves to a validated ingest boundary (`parseEvent` + cross-reference to genesis ids + magnitude guards). Event-sourcing chosen over SQLite / mutable store / dated snapshots. **Amended (cash-settlement):** verbs 3→6, the cash leg rides atomically on the trade leg (`funding`/`settlement` now required), the fold mutates reserves but stays pure, and a durable-log migration/versioning contract lands — `schemaVersion` marker + version-aware parse, a one-shot operator-supplied migration, and a fail-loud read path that refuses to fold a partial log (no defaulted cash leg; append-only preserved). **Amended (realized-P&L):** verbs 6→7 (`InvalidationMarked`, latest-wins), the fold emits a third persisted read-model output `closedPositions[]` (realized = proceeds − Σ lot USD cost, descriptive-only, never added to NAV) plus optional `PositionRecord` fields (`openedAsOf`/`strategy`/`invalidation`), the persisted `direction` spelling is ratified as `below`/`above`, and `InvalidationMarked` is recorded as a v2-era additive verb (`EVENT_SCHEMA_VERSION` stays `2` — no existing record shape changes, no migration). **Amended (trim/add):** verbs 7→9 (`PositionTrimmed`, `PositionAddedTo`), the fold now mutates open-position lots (partial removal / lot append) and emits **partial** `closedPositions[]` rows (`partial: true`) sharing the surviving position's lineage id; trade-offs recorded (trader-directed-*between* vs pro-rata-*within* tier removal; full-retirement REJECT vs alias-to-`PositionClosed`); `EVENT_SCHEMA_VERSION` stays `2` (additive verbs, no record-shape change, no migration — the `InvalidationMarked` precedent). **Amended (Head Digest):** the portable-durable-log increment commits a *derived* **Head Digest** breadcrumb (`head-digest.json`, `deriveHeadDigest`) alongside the log each ingest — carrying `fundValueUsd` (from the canonical composition report), open/closed counts, head event id, and writing-app version — re-derivable, overwritten in place, with **no read-back validation and no engine reader**, so ADR-003's rejection of dated snapshots-as-truth is honored not contradicted (a file nothing folds back cannot become a shadow source of truth); elevates the anti-drift equality `headDigest.fundValueUsd === buildCompositionReport(folded).totals.fundValueUsd` to a named ADR invariant (analogous to the blank-the-closed-book lock). See ADR-006 for the private sibling-repo substrate + commit-per-ingest contract. |
| [ADR-004](./ADR-004-preferences-sidecar.md) | Preferences sidecar: trader policy as a durable artifact beside the event log | product | Accepted | Trader policy (profit-split ratio, loss-netting `splitBasis`) is persisted in a second durable artifact `data/preferences.jsonl` beside the event log, with its own append-only + on-load-validation contract and a pure `pickPolicyAsOf(prefs, asOf)` as-of selector. Policy lives OUTSIDE the immutable log so the fold stays pure and the log folds standalone to the pure #90 book; the profit-split obligation is a compose-time, descriptive-only derivation, never re-added to NAV. Supersedes the grill's genesis-field idea and the deferred `ProfitPolicySet` 8th verb. Trade-offs: log-purity + no 8th verb vs a folded verb; `effectiveAt` time-versioning vs an immutable genesis field. ADR-001 split: `pickPolicyAsOf`/`composeProfitSplit` pure in `@numisma/engine`, sidecar IO (`preferences.ts`) in `@numisma/tui`. |
| [ADR-005](./ADR-005-two-plane-price-model.md) | Market data is not fund history: the two-plane price model | product | Accepted | Automatically-fetched prices enter through two decoupled planes with separate cadences: a disposable, re-fetchable price store (`data/prices/`) upserted every fetch at a configurable fetch cadence, and the sparse `PriceMarked` valuation mark emitted at a separate mark cadence through the existing validated inbox (no engine/schema change). Raw quotes are kept OUT of the append-only log as disposable data and are allowed to diverge intraday from the sparse mark. Mark-instant contract: at most one mark per instrument per mark period, `asOf` anchored to a configured trading-day timezone (not the provider's UTC candle day), self-enforced by the deterministic `pm-<id>-<asOf>` id; concrete timezone/threshold are config, the invariant is not. Rejected: folding candles into the log (bloat, slow fold, conflates valuation decision with disposable observation). ADR-001 split: `quote → PriceMarkedEvent`/symbol resolution/MXN derivation pure in `@numisma/engine`, fetch/IO/scheduling in the runtime. |
| [ADR-006](./ADR-006-private-sibling-data-repo-commit-per-ingest.md) | The private sibling data repository and commit-per-successful-ingest persistence contract | product | Accepted | The durable log lives in a **private sibling git repository** (`~/Dev/accumulus`, the **Log History**) discovered via a configurable `NUMISMA_DATA_DIR`; every successful ingest that appends ≥1 event best-effort auto-commits the four durable text files (`genesis.json`, `events.jsonl`, `preferences.jsonl`, `head-digest.json`) under the operator's own git identity (no `--author`, no Co-Authored-By) then best-effort pushes. `dataDir` resolution is an invariant: default **absolute + homedir-derived** (`~/Dev/accumulus/data`, never CWD-relative, never a hardcoded `/Users/...`), `NUMISMA_DATA_DIR` override wins in **both planes** (tui + price-feed) with identical `~`-expansion + empty/whitespace fall-through, and a relative override rejected loud. Best-effort contract: **never-throws / never-blocks / never-corrupts-the-already-durable-append**, ordering append → Head-Digest write → scoped stage → commit → push (each failure a terminal loud-warn), never-blocks made a **code fact** (`GIT_TERMINAL_PROMPT=0` + push timeout). Allowlist `.gitignore`: the four durable files tracked, `prices/`/`inbox/`/`ingested/`/`*.tmp`/`*.quarantine` ignored — the disposable cache structurally cannot enter history. Rejected: object-store/DB (git gives cheap locate-when/go-back free); nested/same-repo (repo-in-repo footguns / public-history privacy leak); decoupled batch commit (loses in-hand provenance); encrypt-before-commit (privacy = private-repo access control; plaintext history is permanent, forward encryption does not scrub the past). Consequences: the `LogStore` persistence-policy port is an anticipated ADR-001-style follow-on (local git-CLI adapter now, GitHub-API later); the pure `resolveDataDir(env?)` resolver moves into `@numisma/engine` now to kill the byte-identical duplication. Pairs with the ADR-003 **Head Digest** amendment. |
