| [ADR-005](./ADR-005-two-plane-price-model.md) | Market data is not fund history: the two-plane price model | product | Accepted | Automatically-fetched prices enter through two decoupled planes with separate cadences: a disposable, re-fetchable price store (`data/prices/`) upserted every fetch at a configurable fetch cadence, and the sparse `PriceMarked` valuation mark emitted at a separate mark cadence through the existing validated inbox (no engine/schema change). Raw quotes are kept OUT of the append-only log as disposable data and are allowed to diverge intraday from the sparse mark. Mark-instant contract: at most one mark per instrument per mark period, `asOf` anchored to a configured trading-day timezone (not the provider's UTC candle day), self-enforced by the deterministic `pm-<id>-<asOf>` id; concrete timezone/threshold are config, the invariant is not. Rejected: folding candles into the log (bloat, slow fold, conflates valuation decision with disposable observation). ADR-001 split: `quote → PriceMarkedEvent`/symbol resolution/MXN derivation pure in `@numisma/engine`, fetch/IO/scheduling in the runtime. |
| [ADR-006](./ADR-006-private-sibling-data-repo-commit-per-ingest.md) | The private sibling data repository and commit-per-successful-ingest persistence contract | product | Accepted | The durable log lives in a **private sibling git repository** (`~/Dev/accumulus`, the **Log History**) discovered via a configurable `NUMISMA_DATA_DIR`; every successful ingest that appends ≥1 event best-effort auto-commits the four durable text files (`genesis.json`, `events.jsonl`, `preferences.jsonl`, `head-digest.json`) under the operator's own git identity (no `--author`, no Co-Authored-By) then best-effort pushes. `dataDir` resolution is an invariant: default **absolute + homedir-derived** (`~/Dev/accumulus/data`, never CWD-relative, never a hardcoded `/Users/...`), `NUMISMA_DATA_DIR` override wins in **both planes** (tui + price-feed) with identical `~`-expansion + empty/whitespace fall-through, and a relative override rejected loud. Best-effort contract: **never-throws / never-blocks / never-corrupts-the-already-durable-append**, ordering append → Head-Digest write → scoped stage → commit → push (each failure a terminal loud-warn), never-blocks made a **code fact** (`GIT_TERMINAL_PROMPT=0` + push timeout). Allowlist `.gitignore`: the four durable files tracked, `prices/`/`inbox/`/`ingested/`/`*.tmp`/`*.quarantine` ignored — the disposable cache structurally cannot enter history. Rejected: object-store/DB (git gives cheap locate-when/go-back free); nested/same-repo (repo-in-repo footguns / public-history privacy leak); decoupled batch commit (loses in-hand provenance); encrypt-before-commit (privacy = private-repo access control; plaintext history is permanent, forward encryption does not scrub the past). Consequences: the `LogStore` persistence-policy port is an anticipated ADR-001-style follow-on (local git-CLI adapter now, GitHub-API later); the pure `resolveDataDir(env?)` resolver moves into `@numisma/engine` now to kill the byte-identical duplication. Pairs with the ADR-003 **Head Digest** amendment. |
| [ADR-007](./ADR-007-hosted-read-projection-of-private-fund-data.md) | Hosted read-projection of private fund data | product | Accepted (refined by ADR-008 2026-07-07; amended 2026-07-24) | **The gate** before any real fund data leaves the machine. Permits an internet-reachable, cloud-hosted, single-tenant read-only projection under guardrails: the append-only log stays the sole permanent system of record (ADR-003/006) and the hosted DB is a **disposable, re-projectable view** fed by **one-way sync** (local fold → cloud); for v1 only the **folded `CompositionReport`** is pushed, **never raw events** (smaller blast radius than the deferred event-replication iteration, which re-triggers this ADR when it lands); one-way enforced **structurally** via split creds (read-only web cred vs. sole write-cred on the local push job); web secrets are a **second regime** disjoint from the local provider keys. DB corruption is a non-event (re-project); a read-model schema change is a re-push, never a migration. Rejected: localhost-only (dead — remote mobile forces reachability), self-hosted tunnel (fails portfolio/SaaS goals), hosting the canonical log. Pre-deploy security controls (auth, encryption-at-rest, secret manager, rate-limit) are a **required follow-on this ADR gates**, not decided here. **Amended (payload narrowing):** the gated security pass (ADR-011) is complete; the pushed payload is narrowed to `Pick<CompositionReport, "totals" \| "dashboard">` (schema version 1 → 2) to restore the blast-radius paragraph to literal truth after `CompositionReport` silently grew `invalidationWatch`/`strategy`/`closedBook` past what this ADR accounted for — nothing decided the drift, and a forbidden-key contract test now keeps the narrowing durable across future engine growth. |
| [ADR-008](./ADR-008-auth-store-separation-for-the-hosted-web-app.md) | Auth-store separation for the hosted web app | product | Accepted | **Refines ADR-007.** ADR-007's "web holds the read-only cred" is literally true only of the *projection* store; the live web surface holds **two** creds against **two physically separate** databases — a **read-write** cred on a self-hosted Better Auth `numisma_auth` DB (`user`/`session`/`account`/`verification`) plus the ADR-007 **read-only** cred on `numisma_projection` (`composition_snapshot`). Auth store and projection store are **provably disjoint** (auth path never touches `PROJECTION_*`; the RW auth cred cannot reach the projection table) — proven on local Postgres and live Neon. Physical DB separation is the mechanism that keeps ADR-007's one-way guarantee literal. Rejected: third-party auth regime (off-ethos, new vendor/secret regime); auth tables in the projection DB (would force an RW cred on the projection, destroying the one-way guarantee). The auth DB is **not** a disposable re-projectable view (single-account, tiny, **no fund data**), which does not weaken ADR-007 §8.2's disposability claim about the projection DB alone. |

| [ADR-011](./ADR-011-single-tenant-hosted-security-posture.md) | Single-tenant hosted security posture | product | Accepted | **Resolves the ADR-007-gated security pass.** Against an untargeted-automation adversary (scanners, credential stuffing on `*.vercel.app`), two headline decisions: **no lockout** — with exactly one account, lockout hands an anonymous attacker a permanent kill switch on the fund view, so window-based, DB-backed rate limiting (`storage: "database"`, in-memory is worthless on serverless) degrades attacker throughput without ever closing the owner's door; **cost over availability** — an explicit Neon spend threshold suspends the database rather than letting attack traffic run up a bill, chosen deliberately ("I prefer non availability over surprising bills") so a future outage is verified against the runbook, not "fixed" by raising the cap. Supporting posture: obscurity is not sized as a control (a CV-linked URL is a known URL); production stays publicly reachable while previews get Vercel Deployment Protection (two auth systems in series fails exactly when phone access is needed); rotation is trigger-based, never calendar-based. Named deferrals with triggers, not omissions: passkey (URL publicly linked, or a second operator), Pro-tier edge WAF (sustained attack traffic, or a second tenant), a dedicated secret manager (a second operator). |
| [ADR-012](./ADR-012-reserve-opened-tenth-event-verb.md) | `ReserveOpened`: the tenth event verb births an empty cash container | product | Accepted (implementation at `assurance: prototype` on an unmerged branch) | Closes a real asymmetry ADR-003 never named — the log could birth a Position after t0 (`PositionOpened`) but not a Reserve, since every Reserve reference required genesis pre-existence. **`ReserveOpened`** mints an **empty** cash container (`{id, portfolioId, tempo, executionMode, accountId, currency}`, no lots, no funding leg) that is **NAV-neutral by construction** (`InvalidationMarked` is the precedent for a capital-moving-nothing verb); movement then reuses the existing `Transfer`, which needed no change. Answers ADR-004: a Reserve is capital structure, not policy, so it belongs in the log the way `ProfitPolicySet` did not. Rejected: editing the immutable genesis seed (rewrites t0); `Redistribute`, one verb that creates-and-moves atomically (its creation half is conditional — a silent create-or-don't branch, and it can't express open-now-fund-later); a mandatory opening balance symmetric with `PositionOpened` (makes a Reserve birthable only by draining another, false for a new venue). `EVENT_SCHEMA_VERSION` stays `2` (additive verb, no migration). **The prototype build found a provenance-laundering bug in the decision's own literal spec:** "no lots" taken literally (`lots` absent, not empty) would have made `applyReserveDelta`'s untiered-early-return (`fold.ts:85`) swallow every incoming `Transfer`'s tier — fixed by inserting `lots: []` (truthy, so the first credit tiers correctly; canonical normalization still reads length-0 as untiered). Currency-mismatch-against-account is a hard reject at ingest (`crossref.ts`), not the read model's silent exclude-with-warning. Validated through the real ingest path against a copy of the durable data: Capital 33.10%→52.01%, Pulse 23.83%→4.93%, NAV delta exactly 0. |
